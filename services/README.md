# services/

A catalog of concrete, **sellable** offerings — drawn from real scoped work,
signed agreements, pitches, and brainstorms.

This is not `knowledge_base/`. That holds theory and frameworks. This holds
things someone has paid for, or could.

Why keep it: when you are working out what to sell a new prospect, reasoning
from precedent beats inventing something. Read this directory before you invent
an offering.

## Lifecycle

`idea` → `pitched` → `scoped` → `delivered` → `proven`

One file per service. Governed by the `services-catalog` skill, which also
defines the trigger points where this must be updated — creating a project,
ingesting a proposal, brainstorming an offer.
